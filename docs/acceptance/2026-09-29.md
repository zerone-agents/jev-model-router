English | [简体中文](2026-09-29.zh-CN.md)

Scope: source revision `7a483aeb7a7a84067f22cb8e784811feb639be0c`, official TypeSafe Jev `jev-1.13.0`, Alibaba OpenAI-compatible generation with `qwen3.8-flash` and `qwen3.8-max`. The experiments used local, isolated SQLite configurations and the default balanced template. This summary records historical observations; the reusable inspect mode was added afterwards and tested with mocks, not used to produce these historical figures.

The routing gate was fixed before execution: ≥22/24 hits, ≥10/12 per class, ≥10/12 stable repeated choices and no call/invalid-choice errors. It passed without prompt tuning. Both candidates were eligible for every Jev choice. Model descriptions assumed Max was stronger, more expensive and potentially slower; Flash cheaper and faster. These assumptions are not measured prices or latency. The public [routing assets](../../evals/routing/README.md) preserve tasks and descriptions.

The [Agent fixtures](../../evals/agent/README.md) exposed separate issues: prompt-only JSON answers often had Markdown fences; schema-constrained answers were parseable but did not guarantee correctness. Max twice allocated more stock than available. Auto twice guessed dependent tool arguments before receiving the source, then recovered to a correct answer. A subsequent first-turn diagnostic made fifteen successful calls and observed identical provider request bodies for auto and fixed Flash. That did not reproduce the error and does not establish a fix or vendor-side cause. Original failures remain part of the record.

Earlier 4,096/8,192-token experiments ended with truncated, empty answers. Those are incomplete runs, **not evidence that a model cannot solve the task**. With caller token caps removed and full streamed output awaited, all six reasoning answers were correct. Do not infer capability, actual cost or economic benefit from token counts alone. No economic-benefit acceptance was performed.

This supports small-sample routing preference conformance and a diagnostic quality baseline, not production-wide correctness, privacy/security guarantees, or automatic closure of [Issue #1](https://github.com/zerone-agents/jev-model-router/issues/1). The subsequent final end-to-end sample is recorded below. Detailed prompts/responses, request IDs, usage, per-call timings and temporary traces stay in ignored `docs/validation/`; only synthetic fixtures and this reviewed summary are public.

Contemporaneous conclusions: [complete answers](https://github.com/zerone-agents/jev-model-router/issues/1#issuecomment-5885437566), [Agent workflows](https://github.com/zerone-agents/jev-model-router/issues/1#issuecomment-5885590333), [dependency diagnostic](https://github.com/zerone-agents/jev-model-router/issues/1#issuecomment-5885772087), [routing acceptance](https://github.com/zerone-agents/jev-model-router/issues/1#issuecomment-5886010901).

## Final end-to-end spot check

After #6, revision `c0b25f2d2ea4911bc0a23520d101bd224405053f` ran four actual auto generations: two simple and two complex tasks from the public routing set. Original task text, model descriptions and balanced template were unchanged. Rubrics were fixed before calls; see the [spot-check fixtures](../../evals/end-to-end/README.md). Only initial attempts were scored: no inspect-then-explicit substitution, selective retries or caller token cap. Evaluation first-event/idle limits were 1,800 seconds, not production defaults.

| Check | Result |
| --- | --- |
| Expected selection | 4/4: Flash for simple, Max for complex |
| Complete SSE, stable public model, no stream error | 4/4 |
| Strict-schema extraction | 1/1, correct order ID and integer quantity |
| Routing record linkage | 4/4, jev_choice, both candidates, unchanged version |
| Final answer quality | 2/4: simple answers correct; both complex designs failed review |

Both complex answers completed normally; their failures were not truncation:

- The event-processing answer covered transactions and recovery but contradicted itself on retaining event identity across retries. A fresh identity for the same retried operation bypasses durable deduplication. It failed the pre-fixed material-contradiction rule.
- The streaming-proxy answer did not specify a first-body timeout for a connected, header-only upstream, nor clearly exclude a race between committing failure and emitting a successful end marker. Its state transitions and examples did not establish the required atomic boundary.

Complex answers were manually reviewed in full against the fixed rubric. Generated design code was not compiled or executed; these gaps are not findings against this repository's implementation. Routing/protocol spot checks passed with no new router defect observed, while answer quality did not fully pass. Four samples are not a population success rate, performance commitment or proof of improvement over fixed models. Economics remain a separate study. Original answers and detailed grading remain local.
